## Purpose

发现指定日期范围内与研究方向相关的新论文，保留确定性的抓取与评分结果，只为必读论文生成笔记，再汇总为可追溯的 Obsidian 日报。

## Steps

### 0. 解析范围

把用户表达转换为 `DAYS`：今日为 1，过去 3 天为 3，过去一周为 7，过去两周为 14；未指定时为 1。记录目标日期和时间范围，后续输出不得静默扩大该范围。

### 1. 抓取与评分

运行现有脚本；不要修改脚本或其打分规则：

```bash
python3 skills/1-literature/daily-papers/fetch_and_score.py \
  --days {DAYS} \
  --output Workbench/daily/.candidates.json
```

解析 `Workbench/daily/.candidates.json`，确认它是有效 JSON 数组，并保留 stderr 作为失败诊断。空数组时区分“范围内确无新论文”（例如周末 arXiv 无更新）和网络/上游失败；后者不得伪装成“无论文”。

脚本在相同目录维护 `.history.json`：单天模式按 30 天窗口过滤已总结论文，多天模式不应用该过滤；不要绕过、重置或手工重写历史状态。

### 2. 快速分流

只根据候选条目的标题、摘要、来源和 score 做轻量分流：

- **要精读**：强相关，且方法有新意或结果显著。
- **可跳过**：弱相关、novelty 有限或仅 marginal improvement。

对每篇只写一句分流理由。与所有研究兴趣均无关且 score 不高的候选可以跳过，但仍计入抓取与跳过统计。

### 3. 为必读论文生成笔记和点评

对每篇“要精读”论文执行 `paper-digest`；若已存在论文笔记，只读取并使用该笔记，不覆盖。点评必须基于完整笔记正文，而不是只依据摘要。

默认顺序处理。仅当运行时提供并行工作能力、用户授权并行、论文任务彼此独立、各任务写入不同的笔记和 assets，且不会并发写日志/历史/日报等共享文件时，才可并行。共享日志由协调过程串行追加；任一条件不满足就顺序执行。

每篇返回以下点评块：

```markdown
### {短标题}
- **Title**: {完整标题}
- **Institutes**: {institutes}
- **Source**: [link]({url})  {来源徽章}   **📒 论文笔记**: [[{笔记文件名}]]
- **核心**: 3-5 句，核心 idea + 主要结果，避免黑话
- **锐评**: 方法硬伤、claim 与证据是否匹配、与已有工作的本质区别，以及关键数字
- **Rating**: `3` 🔥 / `2` 👀 / `1` 💤 ，{一句话理由}
```

来源徽章固定为：`hf-daily` → `📰 HF Daily ⬆️ {hf_upvotes}`；`hf-trending` → `🔥 HF Trending ⬆️ {hf_upvotes}`；`arxiv` → `📄 arXiv`。

点评要像严谨而尖锐的 senior researcher：判断明确；夸奖必须指出设计或数字；批评必须指出不成立的假设、缺失实验或证据不足的 claim。不得为追求“毒舌”而虚构缺陷或数据。

### 4. 汇总日报

先读取 `references/tags.md` 和 `references/obsidian-syntax.md`。将结果写入 `Workbench/daily/YYYY-MM-DD.md`；同一目标日期的工作流生成文件可以重建，但不得覆盖其中可识别的用户手写内容，若无法安全区分则停止并请求确认。

```markdown
---
date: YYYY-MM-DD
tags: [daily-papers, tag1, tag2, ...]
---
# 🔪 今日总结

{2-3句总结}

## 评分表

| Rating | 论文 |
|--------|------|
| 🔥 `3 - Foundation` | [[#{短标题}]]（理由） |
| 👀 `2 - Frontier` | [[#{短标题}]]（理由） |
| 💤 `1 - Archived` | [[#{短标题}]]（理由） |

## 论文点评

{按评分表顺序原样拼接单篇点评块}

## 已跳过论文

| 论文 | 跳过原因 |
|------|----------|
| ... | ... |
```

### 5. 追加日志

串行追加到 `Workbench/logs/YYYY-MM-DD.md`；不存在时先写 `# YYYY-MM-DD`：

```markdown
### [HH:MM] daily-papers
- **input**: {DAYS} 天
- **output**: [[Workbench/daily/YYYY-MM-DD]]
- **observation**: 抓取 K 篇，精读 N 篇（rating 3: X / 2: Y / 1: Z），跳过 M 篇
```

向用户报告同一组统计，并说明任何抓取、笔记或指标降级。

## Guard

- `DAYS` 必须是与用户请求一致的正整数；不要为增加候选数而扩大日期范围。
- 网络或上游失败时保留诊断并停止或明确降级，绝不把失败解释为“范围内无论文”。
- 以稳定标识（优先 arXiv ID，其次 DOI、规范化标题）去重；尊重 `.history.json`，不得重复生成或重置历史。
- 不覆盖已有论文笔记、assets 或可识别的用户手写内容；只处理本次候选和目标日报、日志，不批量改动其他笔记。
- `.candidates.json` 是瞬态候选文件，不作为论文笔记发布；`.history.json` 是持久状态，不得当作临时文件删除。只清理本次创建且路径已确认的瞬态文件。
- 任何可选并行都必须同时满足运行时能力、用户授权、任务独立、无共享写入；顺序执行始终是后备方案。

## Verify

- [ ] `Workbench/daily/.candidates.json` 存在、可解析、非空；若为空，已给出来自 stderr/上游状态的原因并停止生成日报。
- [ ] 候选已按稳定标识去重，`.history.json` 仍是有效 JSON，且单天模式未重新纳入 30 天窗口内已总结论文。
- [ ] 每篇“要精读”论文都有对应现有或新生成的 `Papers/*.md`；未覆盖已有笔记，失败项已明确记录。
- [ ] 每个点评中的核心、数字和批评都可回溯到对应完整笔记；生成笔记符合其模板且无残留占位符。
- [ ] `Workbench/daily/YYYY-MM-DD.md` 已生成，frontmatter 可解析，评分表锚点与 `### {短标题}` 完全匹配，评分统计与点评块一致。
- [ ] 跳过表覆盖所有未精读候选，抓取 K = 精读 N + 跳过 M。
- [ ] 日志只追加一次，日报、日志和用户报告中的 K/N/X/Y/Z/M 一致。
