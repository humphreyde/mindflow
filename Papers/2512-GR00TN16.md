## 一句话总结

> GR00T N1.6 用更强 VLM、更深动作 DiT、相对动作和更多多本体数据推进真机部署，并把归一化、过拟合、DAgger 与异步 RTC 总结为关键工程经验。

---

## 核心贡献

1. **扩大动作模型容量**：动作 [[DiT]] 从 16 层增至 32 层，删除 N1.5 的 4 层 post-VLM transformer adapter。
2. **调整语义主干训练**：采用支持原始宽高比和 flexible resolution 的内部 Cosmos-2B VLM 变体，并在预训练中解冻顶部 4 层。
3. **改用相对动作**：多数 embodiment 预测 state-relative action chunks，以改善动作平滑性和精度。
4. **强调部署配方**：扩展多本体数据，并明确记录统计量选择、正则化、DAgger 和 [[Real-time Action Chunking|RTC]] 的实际取舍。

---

## 问题背景

### 要解决的问题

[[Papers/2503-GR00TN1.5|GR00T N1.5]] 已改善语言 grounding 和低数据适配，但更复杂的双臂操作、humanoid [[Loco-Dexterous Manipulation|移动操作]]与异步部署仍受到动作容量、动作参数化、数据覆盖及 sim/real 分布偏移限制。

### 本文的动机

N1.6 不只扩大模型，而是同时修改 VLM、DiT、动作坐标、数据 mixture 和 post-training recipe。其技术页最有价值的部分，是把真机部署中容易被 benchmark 掩盖的工程因素明确列出。

---

## 核心技术

### 模型架构

| 组件 | N1.5 | N1.6 |
|---|---|---|
| Base VLM | Eagle 2.5，冻结 | 内部 NVIDIA Cosmos-2B 变体，预训练时解冻顶部 4 层 |
| 图像输入 | 固定预处理 | 原始宽高比、flexible resolution |
| Action DiT | 16 层 | 32 层 |
| Post-VLM adapter | 4 层 transformer | 移除 |
| 动作参数化 | 以 absolute action 为主 | 多数本体使用 state-relative action chunks |

技术页称 VLM 为内部 Cosmos-2B 变体，公开仓库则通过 `EagleBackbone` 与 `Eagle-Block2A-2B-v2` 暴露相关配置，命名并不完全一致；不能仅按名称断言公开 checkpoint 与内部训练实现完全等价。

### 数据扩展

![GR00T N1.6 pretraining data distribution](https://research.nvidia.com/labs/gear/n1_6/training_data_distribution_v3.svg)

在 N1.5 mixture 之上，N1.6 新增数千小时遥操作或仿真数据：

- Bimanual YAM arms；
- AgiBot Genie-1；
- BEHAVIOR suite 中模拟的 Galaxea R1 Pro；
- Unitree G1 whole-body loco-manipulation。

网页还展示了插 GPU rail、摆放餐具、折 T 恤、双手交接、收拾餐桌、装水果，以及移动取放物体等 rollout。它们证明任务覆盖扩大，但视频本身不提供重复运行统计。

### 训练配置

| 阶段 | Steps | Global batch size |
|---|---:|---:|
| Pre-training | 300K | 16,384 |
| Task-specific post-training | 通常 10K–30K | 不超过 1K |

报告没有公开与 N1/N1.5 完全对齐的总数据小时数、完整 optimizer 配置和逐项消融。

### 相对动作的收益与风险

多数 embodiment 改为预测相对于当前 state 的动作块。官方经验是动作更平滑、更准确，但小数据下也更容易累计误差，导致策略难以回到正确状态。它不是无条件优于 absolute action，需要结合数据规模、闭环频率和纠错训练评估。

### Post-training 与部署经验

- **归一化统计**：下游分布接近预训练数据时，pre-trained statistics 可能更好；分布差异大时应改用 post-training statistics，否则模型可能 underfit。
- **防止过拟合**：N1.6 收敛更快，但需要更强 state regularization、数据增强和 pretraining-data co-training。
- **分布修正**：真实 rollout 表现不足时，官方推荐用 [[HG-DAgger|DAgger]] 收集策略诱导状态下的修正数据。
- **异步执行**：train-time 与 test-time RTC 可改善动作连续性和鲁棒性，N1.6 在 Unitree G1 和 Bimanual YAM 中使用该技术。
- **语言标注**：更细粒度 subtask annotation 有帮助，但多任务语言遵循和 OOD 泛化仍未达到稳健水平。

## 实验

### 官方技术页的证据边界

技术页声称 N1.6 在仿真操作、Bimanual YAM、AgiBot Genie-1 和 Unitree G1 上优于 N1.5，但页面没有给出统一的跨版本数值主表。因此该结论目前属于第一方定性总结。

### 公开仓库 Benchmark Recipes

| 公开 recipe / checkpoint | 结果 |
|---|---:|
| LIBERO Spatial | 97.65% |
| LIBERO Goal | 97.5% |
| LIBERO Object | 98.45% |
| LIBERO 10 Long | 94.35% |
| SimplerEnv Bridge | 62.07% |
| SimplerEnv Fractal | 67.66% |
| RoboCasa Panda/Omron（base checkpoint） | 66.22% |
| GR-1 Tabletop 24 tasks（base checkpoint） | 47.6% |

这些数字来自 `n1.6-release` 仓库中的 benchmark README，混合了 base checkpoint 与下游 fine-tuned checkpoint，评测协议也不同于 N1/N1.5 技术页，不能拼成严格的跨版本提升曲线。

### N1.6.1

N1.6.1 只删除 Dockerfile 和 `pyproject.toml` 中的悬空引用，属于工程修复，不是新模型或训练版本，因此不单独建立论文笔记。

## 批判性思考

### 优点

1. 技术变化紧扣真机瓶颈：模型容量、动作坐标、归一化、分布偏移和异步执行被一起考虑。
2. 多本体数据覆盖从桌面双臂扩展到 humanoid loco-manipulation。
3. 主动披露 relative action 的误差积累和多任务语言泛化不足，没有把工程改动包装成万能解法。

### 局限性

1. 缺少与 N1.5 同协议、同数据、同后训练预算的完整定量对比。
2. 架构、数据和训练 recipe 同时变化，无法确认收益主要来自哪一项。
3. 技术页与公开代码中的 backbone 命名存在差异，公开实现不能被默认视为内部训练栈的完整镜像。
4. 没有给出长时任务的 intervention、恢复率和错误类型统计。

### 潜在改进方向

1. 固定数据后对比 16/32 层 DiT、冻结/部分解冻 VLM 和 absolute/relative action。
2. 单独报告 relative action 的短期平滑性与长时累计漂移。
3. 将 DAgger、RTC 和 pre-training co-training 纳入统一消融。
4. 提供跨 embodiment、跨任务长度的 intervention-free horizon 指标。
