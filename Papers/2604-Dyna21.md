## 一句话总结

> Dyna-2.1 用“VLM 工作流编排器 → DYNA-2 动作策略 → RL 全身控制器”的分层系统，把单项机器人技能扩展为可持续一小时的非线性移动操作工作流。

---

## 核心贡献

1. **从 task 转向 workflow**：目标不再是完成一次抓取或折叠，而是低监督地接管包含数百个子任务、分支和恢复行为的完整工作流程。
2. **统一人类与机器人动作接口**：提出 [[Unified Robot Representation|Unified Robot Representation（URR）]]，用腕、肘、胸部和底盘 footprint 的任务空间姿态连接人类视频、遥操作、策略输出与机器人控制。
3. **面向 teachability 的控制设计**：用人类动作构造 RL 控制器的姿态目标，并把低过冲、硬件迭代和历史数据复用纳入系统设计。
4. **长时工作流推理**：用 [[Workflow Orchestrator|VLM 工作流编排器]]和文本 [[Language Memory|长期记忆]]管理机器状态、任务进度、中断与恢复。

## 问题背景

### 要解决的问题

已有机器人基础模型可以在固定工位完成单项任务，但商业部署真正需要替代的是一个持续工作的 **role / shift**。酒店洗衣房要求机器人在洗衣机、烘干机、折叠台和货架之间移动，同时处理高低位置、机器等待时间、衣物掉落、双层毛巾和任务中断，因此属于 [[Loco-Dexterous Manipulation|移动—灵巧协同操作]]。

报告把 workflow 定义为一种允许人类低频、异步交接的自包含业务流程：人把任务交给机器人后离开，数小时后再回来检查，而不是在旁持续 babysit。

#### Figure 2.2：Workflow Reliability / 工作流可靠性

官方交互图用约 79 个子任务说明成功率复合效应。若各步骤相互独立，且每一步成功率均为 $p$，则完整周期无需人工介入的概率为：

$$
P(\text{cycle success})=\prod_{i=1}^{N}p_i=p^N.
$$

当 $N\approx79$、$p=0.95$ 时：

$$
0.95^{79}\approx1.7\%.
$$
成功率相当低

| 子任务类型 | 每周期估计次数 | 图中成功率 |
|---|---:|---:|
| 毛巾取放 | 约 52 | 95% |
| 折叠与堆叠 | 约 12 | 95% |
| 整叠转移到货架 | 约 3 | 95% |
| 开关机器门 | 约 8 | 95% |
| 启动机器 | 约 2 | 95% |
| 移动篮筐 | 约 2 | 95% |

按每天约 48 个、每个约 30 分钟的周期估算，$48\times79\times(1-0.95)\approx190$ 次人工介入，即大约每 8 分钟一次。**这些数字是可交互可靠性模型，不是 Dyna-2.1 的实测成功率**；图中还明确假设子任务独立，而现实错误往往相关，因此实际结果可能更差。

### 现有方法的局限

- 固定工作站扩大不了工作空间，难以覆盖相隔数米且高度差异明显的多个工位。
- 单一 [[VLA]] 擅长把当前观测映射到短动作块，却不天然维护小时级业务状态。
- 即使单步成功率达到 95%，数十至数百步串联后端到端成功率仍会迅速下降。
- 每个客户的流程不同且会变化；如果新技能、高频控制和硬件升级都依赖重新采集大量真机数据，部署成本难以扩展。

### 本文的动机

Dyna 将问题按时间尺度拆开：低频编排器负责“下一步做什么”，中频动作策略负责“身体目标轨迹是什么”，高频控制器负责“如何稳定地在具体硬件上执行”。这样可以分别利用语言/图像预训练、视频与机器人数据以及仿真 RL。

#### Figure 2.3：Laundry Room Workflow / 洗衣房工作流

报告把一个洗衣周期组织为 13 个决策点和四类长操作循环：

| 阶段 | 触发条件 | 主要操作 | 恢复分支 |
|---|---|---|---|
| A. 装洗衣机 | 洗衣机为空 | 开门、逐条取脏毛巾、放入、关门并启动 | 掉落毛巾从地面送回洗衣机 |
| B. 洗衣机转烘干机 | 洗衣完成且烘干机为空 | 同时开门、逐条转移湿毛巾、关门并启动烘干机 | 掉落后视为脏衣，返回脏衣篮 |
| C. 卸烘干机 | 烘干完成 | 移动篮筐、逐条取出、关闭烘干机并推回篮筐 | 掉落后返回脏衣篮 |
| D. 折叠与上架 | 两台机器运行 | 取毛巾、展平折叠、堆叠，达到数量后上架 | 机器完成时中断折叠并返回机器检查 |

关键并非毛巾加工顺序，而是机器人自身的执行顺序非线性：洗衣机和烘干机按各自时钟完成，折叠必须能被打断；有些决策还依赖数十分钟前观察到、当前已不可见的信息。

## 核心技术

### Taku 机器人硬件

Taku 是为人类工作空间设计的半人形移动操作平台：

- 四轮独立转向的稳定移动底盘；
- 可折叠下身，用于覆盖低层货架和高处空间；
- 两条 7-DoF 手臂，上半身合计 21 DoF；
- 人体尺度的腕、肘和胸部工作空间，便于直接复用人类动作；
- 低减速比行星执行器，使手臂速度和加速度更接近人类动作。

### 分层 Physical Agent 架构

#### Figure 2.4：Ingredients of a Physical Agent / Physical Agent 的组成

| 层级 | 运行频率 | 输入 | 输出与职责 |
|---|---:|---|---|
| Workflow orchestrator | 低于动作策略 | 相机、用户指令、文本记忆 | 决定下一子任务，向策略发送语言指令 |
| DYNA-2 policy | 约 5 Hz | 当前观察、子任务、控制器上下文 | 生成 URR 全身目标轨迹 |
| Whole-body controller | 100 Hz | URR 目标、机器人状态 | 输出关节目标和轮速 |
| Taku hardware | 连续物理系统 | 关节与轮速命令 | 执行动作并返回传感信息 |

人物动作也能直接产生 URR 目标，因此人类数据和策略命令从同一个接口进入底层控制器。这个系统是语义规划、技能生成和动态执行的分层组合，而不是一个从像素直接输出电机命令的单体端到端网络。

### 数据与 Unified Robot Representation

[[Unified Robot Representation|URR]] 在局部一致坐标系中描述随时间变化的身体部件姿态：

- wrists：决定末端位置与方向；
- elbows：约束手臂构型并帮助避障；
- chest：表达躯干姿态；
- footprint：表达移动底盘在工作空间中的位置与朝向。

它具有三个官方强调的性质：

1. **Embodiment-agnostic**：人、humanoid、semi-humanoid 和桌面双臂可以按可观察部件选用同一格式。
2. **保留任务空间约束**：手的位置、手臂构型、躯干姿态和身体在工作空间中的位置都被显式保留。
3. **在等价动作格式间可逆**：只要参考系和初始姿态被保留，就能从相对姿态等价表示恢复这些部件姿态。

#### Figure 3.1：URR Tracking / URR 跟踪

> [!info] 交互图
> [在官方页面查看可旋转的 URR 跟踪图](https://www.dyna.co/dyna-2.1)。半透明机器人表示 URR 命令：夹爪对应手部目标、躯干对应胸部目标、底盘对应 footprint、肘部对应 elbow targets；实体机器人表示由关节状态和里程计重放的实际运动。

**说明**：URR 不先把人类动作拟合成机器人关节，而是保留原始任务空间目标，把可达性和关节协调交给 dynamics-aware controller。这样可减少 retargeting 导致的手—物接触错位。

#### Figure 3.2：The Data Lifecycle Around URR / 围绕 URR 的数据生命周期

| 阶段 | 数据流 |
|---|---|
| 人类/机器人数据入口 | egocentric video、UMI、teleoperation、robot fleet data → URR |
| 模型训练 | URR → action encoding → DYNA-2 policy |
| 模型推理 | DYNA-2 action decoding → URR target trajectories |
| 低层执行 | URR → RL whole-body controller → joint targets + wheel velocities |
| 硬件反馈 | Taku sensing → 上层观察与下一轮决策 |

**说明**：报告称改进版 DYNA-2 policy 由 **100 万小时人类视频**与机器人 fleet data 混合预训练，人类视频中的全身姿态被跟踪并转成 URR 监督。这里的规模和转换质量均为公司报告，未给出数据配比、清洗标准或独立复现实验。

#### 人类示范到机器人执行

同一条人类示范同时服务两个学习环节：

- 对 DYNA-2 policy，它是任务与动作的训练样本；
- 对 RL whole-body controller，它是仿真中的姿态跟踪目标和动作先验。

报告还引用此前 DYNA-2 结果：只用人类视频预训练的 DYNA-2 在从未收集现场数据的固定机器人站点上，zero-shot 通过 87% 的客户验收测试，而 DYNA-1 为 46%。这不是 Dyna-2.1/Taku 的本报告实测对照，应视为前置工作的公司自报结果。

### Whole-body Controller 训练

底层 [[Whole-Body Control|全身控制器]]在 NVIDIA Isaac Sim 中通过 RL 训练。它以人类 URR 动作为姿态目标，并混入合成目标，学习平衡、姿态保持和目标跟踪。奖励可以表达任务优先级，例如手部精度高于胸部精度。

为减小 sim-to-real 差距，训练随机化：

- link mass；
- joint friction 与 damping；
- actuator gain；
- actuator delay。

**说明**：数千个仿真 Taku 在 Isaac Sim 中并行训练 [[Whole-Body Control|全身控制器]]。

#### Figure 3.4：Overdamped versus Underdamped / 过阻尼与欠阻尼

| 响应 | 15 cm 手部阶跃下的行为 | 对模仿学习的影响 |
|---|---|---|
| Underdamped | 越过目标并产生振铃 | 小动作误差被放大，接触操作更不稳定 |
| Overdamped | 平滑逼近且不越过目标 | 抑制策略误差传播，更适合示范采集与执行 |

**说明**：网页中的两条响应曲线是人为构造的，具有相同总 tracking error；它用于说明“总误差相同不等于控制质量相同”，不是控制器消融实验。Dyna 把 no oscillation 设为硬要求。

### 保留旧机器人数据

URR 把关节级运动和硬件限制留给底层控制器，因此硬件更新后理论上只需在仿真中重训 controller，而不用改变 policy action space。但稳定动作空间并不能消除不同控制器的动力学差异，Dyna-2.1 使用两种上下文：

1. **显式 controller conditioning**：metadata prompt 标记每条机器人示范来自哪一代硬件/控制器，让同一 checkpoint 学习不同控制特性，并在部署时切换到目标控制器。
2. **隐式异步上下文**：[[Asynchronous Inference|异步推理]]时额外条件化 future commands，让策略从待执行命令中感知控制器动力学。

这个设计与 [[Papers/2410-Pi07|Pi07]] 的 metadata / prompt steering 有相似精神：不是假设所有数据来自同一个动力学分布，而是显式告诉模型当前应模仿哪一种行为模式。

### DYNA-2 动作策略

DYNA-2 policy 约以 5 Hz 运行，把 orchestrator 给出的当前步骤转换为 URR 全身目标轨迹，再由 100 Hz controller 跟踪。官方将其称为改进版 [[World Action Model]]，但本报告没有披露：

- 模型 backbone 和参数规模；
- 动作表示的具体编码与解码；
- 训练损失；
- 是否在测试时生成未来视频或 latent rollout；
- 是否比较候选未来并执行显式规划。

因此目前能够确认的是“语言条件化策略生成全身目标轨迹”，不能仅凭 WAM 名称断言系统进行了显式世界模型规划。它与 [[Papers/2603-FastWAM|Fast-WAM]] 或 [[Papers/2505-FLARE|FLARE]] 的具体关系也缺少足够技术细节。

### Workflow Orchestrator 与长期记忆

[[Workflow Orchestrator]] 建立在预训练 [[VLM|视觉语言模型]]上，再针对洗衣工作流的分支进行 post-training。它的职责包括：

- 把用户短指令展开成 DYNA-2 policy 能执行的步骤；
- 持续观察房间和当前任务；
- 在洗衣机、烘干机、折叠与上架之间选择下一步；
- 验证步骤是否完成；失败时选择重试、改变方法或改变计划；
- 把进度压缩为文本长期记忆。

编排器低频运行，DYNA-2 在此期间持续执行当前步骤，所以理论上可以替换成更大、更慢、上下文更长的 VLM，而不改变下面两层。

长期记忆记录当天工作中无法从当前图像直接恢复的信息，例如：

- 哪些步骤已经完成；
- 洗衣机和烘干机门的开关状态；
- 哪台机器正在运行；
- 当前已折叠多少条毛巾；
- 中断前正在处理的毛巾或堆叠位置。

## 实验与展示

### 一小时未剪辑洗衣工作流

![Dyna-2.1 一小时未剪辑工作流](https://www.dyna.co/assets/we/workflow-video-poster.jpg)

官方展示了一段一小时未剪辑酒店洗衣房运行，覆盖装载、机器间转移、卸载、折叠和上架。它证明系统至少完成过一次小时级、非线性、移动—操作组合流程，但单次成功案例不能替代重复试验统计。

### 定量信息及其证据等级

| 结果或配置 | 数值 | 证据性质 |
|---|---:|---|
| DYNA-2 policy 频率 | 约 5 Hz | 系统配置 |
| Whole-body controller 频率 | 100 Hz | 系统配置 |
| Taku 上半身 | 21 DoF | 硬件配置 |
| 人类视频预训练规模 | 100 万小时 | 公司自报训练规模 |
| 洗衣周期步骤 | 约 79 | 工作流估算 |
| 95% 单步成功率对应整周期成功率 | 约 1.7% | 独立假设下的模型推算 |
| 95% 单步成功率对应 24 h 人工介入 | 约 190 次 | 约 48 周期/天条件下的模型推算 |
| DYNA-2 vs. DYNA-1 客户验收 | 87% vs. 46% | 前置 DYNA-2 工作的公司自报结果 |
| 新固定站点达到 production bar | 最快 3 天 | 既有部署经验描述 |
| Dyna-2.1 端到端展示 | 1 小时、未剪辑 | 单次案例演示 |

- 端到端延迟、算力、能耗和长期硬件可靠性；
- 模型参数、数据混合比例、训练损失和 post-training 配方。

## 与 VLA / WAM 系统的关系

| 系统 | 主要关注点 | 与 Dyna-2.1 的区别 |
|---|---|---|
| [[Papers/2410-Pi07\|Pi07]] | 通用 VLA、prompt/metadata steering、交互数据与长任务能力 | Dyna-2.1 更明确地把业务调度、技能策略和控制器分成三层；controller metadata 与 steering 思路相近 |
| [[Topics/GR00T-Series-Survey\|GR00T]] | 跨本体 VLA、数据金字塔、flow-matching 动作模型与部署栈 | Dyna 以 URR 作为显式任务空间接口，并突出 workflow orchestration，而非只强调基础模型规模 |
| [[Papers/2505-FLARE\|FLARE]] | 用未来 latent alignment 给动作策略加入隐式世界建模监督 | Dyna-2.1 未披露对应训练目标，不能确认其 WAM 具体采用何种未来预测机制 |
| [[Papers/2603-FastWAM\|Fast-WAM]] | 训练期联合视频—动作建模、测试时可直接动作推理 | Dyna-2.1 展示的是完整 agent stack，技术报告没有给出足以逐项比较的模型细节 |
| 传统行为树/状态机 | 明确规则、可解释的任务编排 | Dyna 用 VLM 和文本记忆处理开放视觉分支，但报告没有比较其可预测性和安全边界 |

题目中的 **end-to-end** 更接近“覆盖完整业务流程”，并不意味着一个神经网络从像素端到端输出电机控制。实际上，分层和接口解耦正是系统的核心。

## 批判性思考

### 优点

1. **问题定义贴近部署价值**：用 intervention-free workflow horizon 衡量机器人是否能替代一段工作，而不仅是单项 benchmark 成功率。
2. **系统分层合理**：语义推理、技能策略和高频动态控制位于各自合适的时间尺度。
3. **URR 很有工程价值**：统一人类动作、跨本体策略输出和底层控制，降低硬件升级造成的数据失效。
4. **重视示范质量**：控制器不仅要追踪误差小，还要无振铃、低过冲，以免策略训练继承不稳定动作。
5. **恢复被视为一等能力**：报告承认长流程中失败不可避免，把 retry、recovery 和 replan 放入系统设计。

### 局限性

1. **证据主要来自展示**：一小时未剪辑视频的说服力高于剪辑 demo，但不足以说明成功率、可重复性和无人值守可靠性。
2. **核心模型不透明**：DYNA-2 被称为 WAM，却缺少架构、损失、future prediction 和 inference 机制。
3. **关键数字容易混淆**：1.7% 和 190 次介入是理论演示，不是 Dyna-2.1 的测量结果；87% vs. 46% 来自此前固定机器人测试。
4. **交互图包含构造示例**：Figure 3.4 的响应曲线和 Figure 3.8 的时间线是说明性材料，不是消融或真实运行日志。
5. **安全与异常覆盖不足**：没有报告不可恢复错误、感知误判、碰撞、网络故障和机器异常的处理边界。

### 潜在改进方向

1. 用 intervention-free time horizon、平均无人工接管时间和恢复成功率评估多次完整 shift。
2. 分别消融 URR、人类视频预训练、controller metadata、future command context 和文本记忆。
3. 报告按步骤类型分解的成功率与错误相关性，而不是假设全部步骤独立同分布。
4. 把 orchestrator 的文本状态与可验证的结构化 world state 结合，减少记忆漂移和视觉误判。
5. 明确 DYNA-2 是否拥有可查询的未来预测、反事实 rollout 或规划接口，从而厘清其 [[World Action Model|WAM]] 定位。
