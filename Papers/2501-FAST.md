## 一句话总结

> 把机器人动作 chunk 当作"图像信号"一样用 [[DCT|离散余弦变换]] + 量化 + [[BPE|字节对编码]] 压成 30 个 token，让自回归 [[VLA]] 也能学高频灵巧任务，并训练出和 [[Pi0|diffusion π0]] 性能相当、训练快 5× 的 π0-FAST。

---

## 核心贡献

1. **诊断"naive tokenization 在高频数据上崩"的根因**: 在一个 cubic-spline 拟合 toy 实验上，作者证明 [[Naive Action Tokenization|逐维逐步分箱]] 在采样率上升时会让"下一 token 的边际信息"趋近零，模型只能学会"复制上一个 token"，从而完全失败 —— 这是 [[OpenVLA]] 在 [[DROID]] 等高频数据集上拟合不动的本质原因。
2. **提出 FAST tokenizer**: 一个**完全分析式、零神经网络**的 robot action tokenizer —— 归一化 → [[DCT|DCT]] → 量化 → 列优先 flatten → [[BPE]] 无损压缩。把 1 秒 50 Hz 双臂动作 chunk 从 700 个 token 压到 53 个（13.2× 压缩），有 2 个不敏感超参（DCT scale、BPE vocab size）。
3. **发布通用 tokenizer FAST+**: 在 100 万条横跨 7 种机器人形态、4 种动作空间（Joint / EE / Camera-frame）、15 / 20 / 50 Hz 控制频率的真实轨迹上训出黑盒 BPE 词典，可作 HuggingFace `AutoProcessor` 三行代码调用，在 100% 未见数据集上仍能稳定压 2× 以上。
4. **训出 π0-FAST 模型**: 把 FAST 接到 [[Pi0|π0]] 的 PaliGemma-3B 上做**纯 next-token-prediction**，在 10000 小时跨形态数据上匹配 diffusion π0 的所有任务性能（含 5 分钟级长时序的洗衣折叠），但训练 GPU 时长降到 1/5；这是第一次自回归 VLA 在高频灵巧任务上和 diffusion VLA 打平。
5. **首次 DROID 零样本通用策略**: 单一 checkpoint 不微调、不 co-train，仅靠语言提示就在三个完全没见过的校园办公室里 zero-shot 完成桌面操作，验证了"高质量 tokenizer + 自回归 VLA"在 in-the-wild 数据上的 scaling 能力。

## 问题背景

### 要解决的问题

VLM-based [[VLA]]（[[RT-2]] / [[OpenVLA]]）天然是 autoregressive next-token predictor，要让它输出机器人动作，必须先把连续动作信号 $a_t \in \mathbb{R}^n$ **离散化成 token 序列**。可这一步在高频（≥20 Hz）灵巧任务上常常导致策略**完全学不会**，作者要解决的就是这个"VLA 卡在 tokenizer 上"的瓶颈。

### 现有方法的局限

1. **[[Naive Action Tokenization|逐维逐步分箱]]**（[[RT-2]] / [[OpenVLA]] / OpenX 系列）：每个动作维度独立分 256 bin，长度 $H$、维度 $d$ 的 chunk → $H \cdot d$ 个 token，50 Hz 双臂任务一秒钟动作就要 700 个 token，**token 间高度相关**导致下一 token 预测的信号几乎为零，模型陷入"复制上一个 token"的局部最优。
2. **学习型 quantization**（如 [[VQ-VAE]] / FSQ tokenizer）：需要额外训练编码器、增加超参，且在跨数据集时要重新拟合；本文 ablation 显示 FSQ 在 high-frequency 任务上仍弱于 FAST。
3. **连续动作 VLA**（[[Pi0]] / [[Diffusion Policy]]）：用 [[Flow Matching]] 或 diffusion 输出连续动作，规避了 tokenization，但需要**单独的 [[Action Expert]]** + 多步采样推理；同时无法直接套用 LLM 后训练（cross-entropy）的所有 trick（RL、speculative decoding 等）。
4. **从未在 [[DROID]] 跑出强 generalist policy**：DROID 是 15 Hz、76k 条多机构数据，naive tokenization 让 OpenVLA 在它上面拟合不动，几乎无人成功端到端训练 generalist。

### 本文的动机

作者从信息论角度切入：autoregressive 训练的有效梯度信号 $\propto I(T_k; T_{<k})$ 的**边际信息**，naive tokenization 让高频信号的边际信息塌缩到 0。要修复这件事，**必须先压缩动作再监督**。语言模型的 [[BPE]] 已经验证"压缩即智能"，那么对连续信号要选一个合适的可压缩表示 —— 作者选了 [[DCT|JPEG 同款]]的频域变换：

- 频域系数稀疏：低频几个系数就能描述整体形状，高频系数大多接近 0
- 解析变换无需训练，detokenize 也是矩阵乘
- 配合 BPE 把稀疏 0 元素全部"折叠"，输出长度可控的密集 token 序列

## 方法详解

### 整体架构

FAST 的"模型"其实就是一个分析式 tokenizer pipeline（**无可学习神经网络**），与下游 [[VLA]] 解耦：

- **输入**: 归一化后的动作 chunk $a_{1:H} \in \mathbb{R}^{H \times n}$（$H$ 为时间步，$n$ 为动作维度）
- **Backbone**: 没有 backbone —— FAST 本身是变换 + 编码，可挂到任意 [[VLA]] 主干（[[Pi0]]、[[OpenVLA]]）
- **核心模块**:
  - [[DCT|离散余弦变换 (DCT)]]：把时间轴信号搬到频域，得到稀疏系数
  - **Quantize-and-Round**：用单一 scale $\gamma$ 控制压缩-保真度
  - **Column-first Flatten**：按"先低频后高频"在维度间交错，让自回归优先预测全局形状
  - [[BPE|Byte-Pair Encoding]]：把稀疏整数序列无损压成密集 token，并把零段"压扁"
- **输出**: 长度 $\bar{k}$ 的离散 token 序列 $[\bar{T}_1, \dots, \bar{T}_{\bar{k}}]$，词表大小 1024（单数据集）或 2048（FAST+ 通用）

下游模型只需把这些 token 当作 VLM 词表里的特殊 token 即可：在 π0-FAST 中，作者直接**覆盖 [[PaliGemma]] 词表里最少用的 token**，复用 LLM 整套训练栈。

### 核心模块

#### 模块 1: [[DCT|Discrete Cosine Transform]] 频域压缩

**设计动机**: 利用机器人动作"低频主导、平滑可压缩"的统计特性，把信息浓缩到少数低频系数，类似 [[VQ-VAE|VQ]] 但完全免训练。

**具体实现**:
- 对归一化后 $a_{1:H}^i$ 的**每一维 $i$ 独立**做 DCT，得到系数矩阵 $C^{i}_{j}$（$i$ 是维度索引、$j$ 是频率索引）
- 量化：$\bar{C}^i_j = \mathrm{round}(\gamma \cdot C^i_j)$，scale $\gamma$ 越大越保真，越小压缩越狠（默认 $\gamma=10$）
- 量化后的矩阵 95% 以上为 0，仅低频区域稀疏非零 —— 这正是 BPE 喜欢的输入

#### 模块 2: Column-first Flatten

**设计动机**: 自回归 next-token 是 sequential 的，**先看到什么决定模型怎么 reason**。作者发现"先全局形状、再局部细节"对长时 rollout 更稳定。

**具体实现**:
- 把 $\bar{C} \in \mathbb{Z}^{H \times n}$ 按**列优先**展平：先放所有维度的最低频系数 $\bar{C}^{1}_1, \bar{C}^{2}_1, \dots, \bar{C}^{n}_1$，再放次低频 $\bar{C}^{1}_2, \dots$，依此类推
- 直觉对照：行优先 = "先把第 1 维所有频率讲完再讲第 2 维"，会让早期解码就被高频噪声干扰；列优先 = "先把每一维的整体形状勾勒出来再补细节"

#### 模块 3: [[BPE|Byte-Pair Encoding]] 无损压缩

**设计动机**: DCT 量化后是稀疏整数串，直接喂模型会有大量"0 token"稀释学习信号；用 BPE 把高频共现的整数 pattern（特别是连续 0）合并成 super-token，类似 LLM tokenizer。

**具体实现**:
- 训练：对训练集所有 flatten 后的整数序列跑标准 BPE 学词典 $\phi$（vocab size 1024）
- 推理：用学好的 $\phi$ 把序列贪心合并成 $\bar{k}$ 个 token
- 可逆性：每一步都可解析逆映射，detokenize 走 BPE 反查 → 反 flatten → 反 round → IDCT，整套流水线**毫秒级**完成
- 同效目标的备选有 Huffman / Lempel-Ziv (gzip)，作者留作 future work

#### 模块 4: 通用版 FAST+

**设计动机**: 单数据集每次重训 BPE 词典虽快，但仍是"摩擦"；目标是给出"现成可用"的 black-box tokenizer。

**具体实现**:
- 数据混合：1M 条 1 秒动作 chunk，来自 7 种 robot morphology（单臂 / 双臂 / 移动 / 双臂移动）、3 种 action space（Joint / EE / Camera-frame）、15 / 20 / 50 Hz 控制频率 + [[ALOHA]] / [[DROID]] / [[Bridge]] / [[OXE]] 公开数据集
- 词表：2048
- 发布方式：`AutoProcessor.from_pretrained("physical-intelligence/fast")`

## 关键公式

### 公式 1: [[Naive Action Tokenization|逐维逐步分箱 tokenization]]

$$
\mathrm{tokenize}(a_{1:H}) = [\mathrm{Bin}(a^1_1), \mathrm{Bin}(a^2_1), \dots, \mathrm{Bin}(a^n_H)] \in \{0, \dots, 255\}^{H \cdot n}
$$

**含义**: 朴素方案 —— 每个动作维度按训练集 1%–99% 分位数划成 256 个等距 bin，得到长度为 $H \cdot n$ 的固定长度 token 序列。

**符号说明**:
- $a^i_t \in \mathbb{R}$: 第 $t$ 步、第 $i$ 维的连续动作值
- $\mathrm{Bin}(\cdot)$: 256 等宽 bin 函数（OpenVLA / RT-2 默认）
- $H, n$: chunk 长度（如 1 s × 50 Hz = 50）与动作维度（如双臂 14）
- 高频高维场景下 $H \cdot n$ 可达数百

### 公式 2: [[DCT|离散余弦变换]] 系数

$$
C^{i}_{j} = \mathrm{DCT}\bigl(a^{i}_{1:H}\bigr), \quad j = 0, 1, \dots, H-1
$$

**含义**: 把第 $i$ 维的时序信号正交分解到 $H$ 个余弦基底上，$j=0$ 对应直流（均值）、$j$ 越大频率越高。机器人动作平滑，故 $|C^i_j|$ 随 $j$ 增大快速衰减。

**符号说明**:
- $C^{i}_{j} \in \mathbb{R}$: 第 $i$ 维信号在第 $j$ 个余弦基上的系数
- $\mathrm{DCT}(\cdot)$: 标准 Type-II DCT，$O(H \log H)$ 可算
- 与 JPEG 压缩使用的变换同源

### 公式 3: 量化 (Quantize)

$$
\bar{C}^{i}_{j} = \mathrm{round}\bigl(\gamma \cdot C^{i}_{j}\bigr)
$$

**含义**: 单一标量 $\gamma$ 同时控制保真度和压缩率 —— $\gamma$ 越大保留越多有效位、压缩越弱；$\gamma$ 越小则更多系数被舍入到 0、压缩越强。论文默认 $\gamma=10$。

**符号说明**:
- $\bar{C}^i_j \in \mathbb{Z}$: 量化后的整数系数
- $\gamma$: rounding scale，论文证明在 $\gamma \in [5, 50]$ 范围内对最终策略性能不敏感
- 这是 FAST 全流水线**唯一**控制 rate-distortion 的旋钮

### 公式 4: Column-first Flatten

$$
[T_k] = \bigl[\bar{C}^{1}_{1}, \bar{C}^{2}_{1}, \dots, \bar{C}^{n}_{1}, \bar{C}^{1}_{2}, \dots, \bar{C}^{n}_{H}\bigr]
$$

**含义**: 把二维稀疏矩阵按"先所有维的最低频，再所有维的次低频…"顺序拼成一维整数序列，保证自回归早期 token 都是描述全局形状的低频系数。

**符号说明**:
- $T_k \in \mathbb{Z}$: flatten 后的第 $k$ 个整数 token（BPE 之前）
- 总长度 $= H \cdot n$，但绝大多数为 0

### 公式 5: [[BPE|BPE 无损压缩]]

$$
\bigl[\bar{T}_{1}, \dots, \bar{T}_{\bar{k}}\bigr] = \mathrm{BPE}\bigl([T_1, \dots, T_{H \cdot n}], \; \phi\bigr)
$$

**含义**: 用学好的 BPE 词典 $\phi$ 把稀疏整数串贪心合并成长度 $\bar{k} \ll H \cdot n$ 的密集 token 序列；$\bar{k}$ 在不同任务上稳定在 30/arm 左右，几乎与控制频率解耦。

**符号说明**:
- $\phi$: BPE 词典，单数据集 vocab=1024，FAST+ vocab=2048
- $\bar{T}_l \in \{0, \dots, |\phi|-1\}$: 最终 action token
- $\bar{k}$: 实际 token 数，随 chunk 复杂度而变（类比文本"长短句不同 token 数"）

### 公式 6: Algorithm 1 — FAST Tokenizer 全流程

$$
\begin{aligned}
&\textbf{procedure}\ \mathrm{FASTTokenizer}(a_{1:H}): \\
&\quad C^{i}_{j} \leftarrow \mathrm{DCT}(a^{i}_{1:H}) &&\triangleright\ \text{compute DCT coeffs} \\
&\quad \bar{C}^{i}_{j} \leftarrow \mathrm{round}(\gamma \cdot C^{i}_{j}) &&\triangleright\ \text{quantize} \\
&\quad [T_k] \leftarrow [\bar{C}^{1}_{1}, \bar{C}^{2}_{1}, \dots, \bar{C}^{n}_{H}] &&\triangleright\ \text{flatten tokens} \\
&\quad \textbf{BPE Training:}\ \phi \leftarrow \mathrm{TrainBPE}\bigl(\mathcal{D} := \{[T_k]\}\bigr) \\
&\quad \textbf{Tokenization:}\ [\bar{T}_1, \dots, \bar{T}_{\bar{k}}] \leftarrow \mathrm{BPE}([T_1, \dots, T_k], \phi) \\
&\quad \textbf{return}\ \text{action\_tokens}
\end{aligned}
$$

**含义**: 整套 tokenization 算法只有 4 行（DCT → 量化 → 列优先 flatten → BPE），所有操作都是闭式可逆的。

**符号说明**:
- $\gamma$: scale 超参，输入
- $\phi$: BPE 词典（推理时已学好；训练时根据 $\mathcal{D}$ 学）
- $\mathcal{D}$: 训练用整数序列数据集
- $\bar{k}$: 最终 token 数（变长）

### 实现细节

- **Backbone**: 主实验 [[Pi0]] (PaliGemma-3B)；ablation 用 [[OpenVLA]] (Prismatic 7B)
- **Action chunk 长度**: 1 秒（不同频率下 $H$ 不同）
- **Token 接入**: 覆盖 VLM tokenizer 中**最少使用的 token**，无需扩词表
- **Loss**: 标准 next-token cross-entropy，**无单独 action loss**
- **Optimizer / LR**: 论文沿用 [[Pi0]] / [[OpenVLA]] 的默认配置（[[AdamW]] + warmup + cosine decay）
- **训练 GPU 时长**: 通用 π0-FAST 为 diffusion π0 的 **1/5**（具体绝对值未披露，但属"千 GPU 小时"量级）
- **推理延迟**: NVIDIA RTX 4090 上单 chunk ~750 ms（vs diffusion π0 ~100 ms），相当于 ~1.3 Hz 控制频率
- **超参鲁棒性**: DCT scale $\gamma \in [5, 50]$、BPE vocab $\in [512, 4096]$ 均无明显性能差异

- **Figure 1 / 10**: 双臂洗衣折叠 5 分钟完整 rollout，多阶段抓取-铺平-对折-堆叠均稳定

## 批判性思考

### 优点

1. **诊断直击本质**: toy 实验 + 信息论解释，把"为什么 OpenVLA 在 DROID 上跑不动"讲得透彻，远比单纯报性能数字有价值。
2. **零神经网络 tokenizer**: 完全分析式，可逆、毫秒级、超参不敏感，工程上把"动作 tokenizer 难训"从问题清单上彻底划掉。
3. **通用 FAST+ 极易用**: HuggingFace `AutoProcessor` 三行代码，已成为后续 [[Pi05]] / [[Pi06]] / [[Pi07]] / [[KI]] 系列论文的事实标准。
4. **首次自回归 VLA 在灵巧任务平 diffusion**: 把"VLA 必须 diffusion 才有戏"这个偏见打破，重新打开 autoregressive VLA 的研究空间。
5. **可解释的 rate-distortion 旋钮**: 只有 $\gamma$ 和 vocab size 两个超参，且都可视化 trade-off 曲线，便于复现和调参。

### 局限性

1. **推理延迟显著**: 750 ms / chunk 等于 ~1.3 Hz 控制更新，**不适合需要快速反应的动态任务**（catching、push recovery）。作者寄望 [[Speculative Decoding|speculative decoding]] / 量化 / 自定义 kernel，但未给出实验。
2. **仅在静态台面任务验证**: 移动操作、人形机器人、灵巧手只在"离线压缩率"上做了观察，没有 policy rollout 验证。
3. **DCT 假设信号平滑**: 对于含**接触瞬变、碰撞冲击**的高带宽数据（如装配、敲击），低频系数可能不足以捕获关键瞬态信息，论文未做相关数据集。
4. **BPE 词典固化**: 通用 FAST+ 在彻底新形态（如非笛卡尔 / 关节耦合极强系统）上是否最优仍待验证；论文也承认 Huffman / LZ 等替代留作未来工作。
5. **缺乏与连续动作 [[Diffusion VLA|diffusion VLA]] 在动态任务上的比较**: 推理时间问题让 FAST 无法直接覆盖所有 use case，论文未量化"高速反应"任务上谁更适合。
6. **闭源数据**: 10000 小时 + 1M chunk 训练集多为 Physical Intelligence 内部数据，社区难以完全复现 generalist 实验。

### 潜在改进方向

1. **接 Speculative / Parallel Decoding**: 用一个小 draft model 一次出多个 action token，把 1.3 Hz 推到 10 Hz+
2. **接 RL post-training**: 离散 token + cross-entropy 让 GRPO / DPO 等 LLM RL 直接可用（[[Pi06]] / [[Pi07]] / [[ConRFT]] 已沿此线展开）
3. **可学习压缩混合**: 在 DCT 基础上再叠一层 [[VQ-VAE]]，让高频残差也被有效捕获，专门服务接触型任务
4. **Token-rate adaptive**: 根据动作复杂度动态决定 $\bar{k}$（类似 LLM 中的 dynamic chunking）
5. **结合 [[Knowledge Insulation]]**: 让 FAST token 做 VLM 监督、flow matching action expert 做精细控制（[[KI]] / [[Pi05]] 已落地）

### 可复现性评估

## 速查卡片

> [!summary] FAST: Efficient Action Tokenization for VLA
> - **核心**: 用 DCT + 量化 + BPE 把机器人动作 chunk 压成 ~30 个离散 token，让自回归 VLA 也能学高频灵巧任务
> - **方法**: normalize → per-dim DCT → round(γ·C) → column-first flatten → BPE，零神经网络、毫秒级、超参不敏感
> - **结果**: 与 diffusion π0 在所有 dexterous 任务持平，训练算力降到 1/5；首个 DROID zero-shot generalist policy；FAST+ 通用 tokenizer 已成事实标准
> - **代价**: 推理 ~750 ms / chunk（~1.3 Hz），动态任务需配 speculative decoding 等加速
> - **代码**: https://github.com/Stanford-ILIAD/openvla-mini ， `AutoProcessor.from_pretrained("physical-intelligence/fast")`
